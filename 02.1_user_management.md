## Création d'utilisateur

Créer un nouvel utilisateur :

```bash
useradd newusername
```

Deux options importantes :

| Option | Rôle |
|--------|------|
| `-d /chemin` | Définir une *home directory* spécifique |
| `-m` | Forcer la **création** de la *home directory* |
| `-s /bin/bash` | Définir le shell de connexion |
| `-G groupe1,groupe2` | Ajouter l'utilisateur à des groupes secondaires dès la création |

```bash
useradd -d /home/test -m username
```

> [!TIP]
> Sur Debian et dérivés, `adduser` est un script interactif construit **au-dessus** de `useradd` : il crée la home, copie le contenu de `/etc/skel`, demande le mot de passe et les informations de l'utilisateur.
>
> ```bash
> sudo adduser username
> ```
>
> `useradd` reste le bon choix dans un **script** (non interactif, comportement identique partout).

## Lister les groupes d'un utilisateur

Lister mes groupes :

```bash
groups
```

Lister les groupes d'un autre utilisateur :

```bash
groups otheruser
```

Voir aussi, en plus détaillé (UID, GID, tous les groupes) :

```bash
id username
```

---

## Modifier un utilisateur

Ajouter un groupe à un utilisateur :

```bash
usermod -aG nouveaugroupe username
```

> [!WARNING]
> Le `-a` (*append*) est **obligatoire** avec `-G`. Sans lui, `usermod -G groupe username` **remplace** la liste complète des groupes secondaires de l'utilisateur et le retire donc de tous les autres — y compris de `sudo`.

Retirer un utilisateur d'un groupe :

```bash
gpasswd -d username groupe
```

ou, sur Debian et dérivés :

```bash
deluser username groupe
```

Autres modifications courantes :

| Commande | Effet |
|----------|-------|
| `usermod -l nouveaunom ancienom` | Renommer l'utilisateur |
| `usermod -s /usr/bin/zsh username` | Changer son shell |
| `usermod -L username` | Verrouiller le compte |
| `usermod -U username` | Déverrouiller le compte |

> [!IMPORTANT]
> Les changements de groupe ne s'appliquent qu'aux **nouvelles** sessions. L'utilisateur doit se déconnecter/reconnecter (ou lancer `newgrp groupe`) pour que ses nouveaux droits soient effectifs.

## Supprimer un utilisateur

```bash
userdel username
```

Supprimer aussi sa *home directory* :

```bash
userdel -r username
```

---

## Lister les utilisateurs de la machine

```bash
cat /etc/passwd
```

Chaque ligne suit ce format :

```text
username:x:1001:1001:Commentaire:/home/username:/bin/bash
    │    │   │    │       │            │            │
   nom   │  UID  GID    GECOS        home         shell
         └─ mot de passe (le "x" renvoie vers /etc/shadow)
```

> [!NOTE]
> Les mots de passe ne sont **pas** dans `/etc/passwd` (lisible par tous) mais dans `/etc/shadow`, sous forme de hash et lisible par root uniquement.
> Un utilisateur dont le shell est `/usr/sbin/nologin` ou `/bin/false` est un compte de service : il ne peut pas ouvrir de session.

## Changer un mot de passe

Changer le mot de passe de son propre utilisateur :

```bash
passwd
```

Changer le mot de passe d'un autre utilisateur — **en tant que root** :

```bash
passwd username
```

Forcer un utilisateur à changer son mot de passe à la prochaine connexion :

```bash
passwd -e username
```

## Gestion des groupes

Créer un groupe :

```bash
groupadd nomDuGroup
```

Supprimer un groupe :

```bash
groupdel nomDuGroup
```

Lister les groupes présents sur la machine :

```bash
cat /etc/group
```

## Changer d'utilisateur

```bash
su - username
```

Le tiret (optionnel) déclenche un **shell de login** : il charge l'environnement complet de l'utilisateur cible et place le terminal dans sa *home directory*.

| Commande | Effet |
|----------|-------|
| `su username`   | Change d'utilisateur mais **garde** l'environnement et le dossier courants |
| `su - username` | Ouvre une session propre, comme une vraie connexion |

> [!TIP]
> La différence entre shell de login et shell interactif détermine quels fichiers de configuration sont chargés (`~/.profile` vs `~/.bashrc`). C'est le sujet du [chapitre 10](10_shell_config.md).

## L'utilisateur root (admin)

Le compte `root` est l'administrateur de la machine. Tout ce qui concerne la gestion du système (ajout d'utilisateur, installation de paquets, configuration des services…) doit être exécuté en tant que root.

> [!CAUTION]
> **Restez root le moins longtemps possible.**
> Le principe est de faire un maximum de choses avec un minimum de droits : une faute de frappe en root peut détruire le système, et un shell root laissé ouvert est une porte grande ouverte.

Deux méthodes possibles :

### 1. Exécuter *une* commande en tant que root — **fortement conseillé**

```bash
sudo commande
```

Je peux aussi préciser l'utilisateur dont je veux emprunter l'identité :

```bash
sudo -u username commande
```

### 2. Changer d'utilisateur — à réserver aux sessions d'administration

```bash
su
```

```bash
su root
```

```bash
sudo su -
```

> [!NOTE]
> Sur Ubuntu, le compte root n'a pas de mot de passe par défaut : `su` échoue, il faut passer par `sudo`.
> La configuration fine de qui peut faire quoi via `sudo` est traitée dans le [chapitre 05 · Sécurité](05_securite.md#sudosudoers).

### Sortir d'une session

```bash
exit
```

ou le raccourci `CTRL + D`.

## Récapitulatif

| Commande | Rôle |
|----------|------|
| `useradd` / `adduser` | Créer un utilisateur |
